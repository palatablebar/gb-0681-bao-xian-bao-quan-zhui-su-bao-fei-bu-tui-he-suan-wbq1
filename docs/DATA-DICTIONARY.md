# 保费补退定义

每份保单有且仅有一条issue基线。change按effective、责任、version选版；同生效日同版本矛盾拒绝。cancel必须引用同保单的change，取消整份变更，不按录入顺序覆盖。区间为[start,end)。年度保费按所在自然年365或366日拆分，跨年强制切段。先求每段精确保费，再最大余额法分配到分，使段合计等于保单总额。paid为已收金额，总应收减已收为补退额，正数补缴、负数退费。

## 撤销后继裁决

同一保单、同一责任上，撤销一条change后，生效日晚于该change的后续change即为其后继批改（显式ref指向被撤销change或其cancel记录时也成立，不作日期限制）。后继批改不会因上游撤销被删除，而是进入撤销链，按下列状态之一呈现：

| 状态 | 含义 | 进入保障链 |
|---|---|---|
| ACTIVE | 无上游撤销，正常生效 | 是 |
| CANCELLED | 被cancel直接撤销 | 否 |
| SUPERSEDED | 同生效日同责任被更高version替代 | 否 |
| PENDING | 上游撤销已到，尚未裁决 | 否 |
| REVERIFIED | 裁决为重新核验后保留 | 是 |
| VOID | 裁决为随上游撤销失效 | 否 |

初始读取仅产生 ACTIVE、CANCELLED、SUPERSEDED、PENDING；有PENDING时整条链不可发布。发布时必须对每条PENDING给出裁决（逐条 `decisions` 或整体 `default`）。裁决会写入运行参数，重跑同一来源得到同一结论，不新增保障或补退。

发布是原子的：校验失败（仍有PENDING、对账未平、结案校验未通过）不写入任何内容，既有已发布链与版本保持不变。版本陈旧返回409 STALE。发布版本号连续递增；再次发布内容相同时不升版。工作台、各阶段接口与结案下载只呈现同一份已发布保障链及其补退结果；无已发布链时只能看到预览，下载返回409 NOT_PUBLISHED。

撤销链与后继链均保留来源行，结案CSV包含“批改链”“撤销链”“裁决”记录：即使后继被判VOID，其记录、上游引用与cancel记录仍可追溯。


## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。
